# TechForce Social — โพสต์อัตโนมัติหลายแบรนด์

ตั้งเวลาโพสต์รูป + ข้อความไป Facebook, Instagram, TikTok, LINE OA และ X ได้หลายแบรนด์จากที่เดียว (เช่น เอเจนซีที่ดูแลเพจให้ลูกค้าหลายราย)

ใช้ได้ 2 แบบ:

| แบบ | เปิดอย่างไร | ได้อะไร |
|---|---|---|
| **โหมดตัวอย่าง** | เปิด [`index.html`](index.html) ในเบราว์เซอร์ตรง ๆ | ข้อมูลจำลอง เก็บในเบราว์เซอร์นั้น ไม่โพสต์จริง — ไว้โชว์ลูกค้า |
| **ใช้งานจริง** | `node server/index.mjs` แล้วเปิด `http://localhost:8787` | เข้าสู่ระบบ · เชื่อมบัญชีจริง · ตัวตั้งเวลาโพสต์ให้แม้ปิดหน้าเว็บ · ข้อมูลเก็บที่เซิร์ฟเวอร์ |

หน้าเว็บเป็น HTML/CSS/JS ล้วนชุดเดียวกันทั้งสองแบบ (รู้เองว่าเปิดผ่านเซิร์ฟเวอร์หรือไม่) · เซิร์ฟเวอร์เป็น Node.js ไม่มี dependency (ต้องใช้ Node 24+)
ดีไซน์ที่เลือก: แบบ C (Autopilot) + หน้าเขียนโพสต์ของแบบ A จาก [`apps/fitness/designs/autopost-options.html`](../fitness/designs/autopost-options.html)

## หน้า

| หน้า | ลิงก์ | ทำอะไรได้ |
|---|---|---|
| โพสต์อัตโนมัติ | `#/autopilot` | กฎโพสต์อัตโนมัติ (เปิด/ปิด สร้าง แก้ ลบ) · โพสต์ที่จะออกต่อไป (ข้ามรอบได้) · ผลลัพธ์ 7 วันรายช่องทาง · ช่วงเวลาที่คนดูเยอะ · แจ้งโพสต์ที่ไม่สำเร็จ |
| เขียนโพสต์ | `#/compose` | อัปโหลดรูปเอง (หลายไฟล์ ลากวางได้ ย่อเหลือด้านยาว 1600px) หรือใช้เทมเพลตของแบรนด์ · ข้อความ + ปุ่มช่วยเขียน · เลือกช่องทาง · โพสต์ทันที / ตั้งเวลา / เวลาดีสุด · ตัวอย่างหน้าตาจริงทุกช่องทาง · เตือนข้อจำกัด (X 280 ตัวอักษร, TikTok ต้องเป็นวิดีโอ, รูปถูกครอป, ลิงก์ใน IG กดไม่ได้, โควตา LINE) |
| ปฏิทินโพสต์ | `#/calendar` | ปฏิทินรายสัปดาห์ รวมโพสต์ที่ตั้งเวลา/โพสต์แล้ว/ไม่สำเร็จ/ร่าง และรอบจากกฎ · กดดู แก้ โพสต์ตอนนี้ ลบ หรือข้ามรอบของกฎ |
| บัญชีที่เชื่อม | `#/accounts` | เชื่อม/ยกเลิกช่องทางของแต่ละแบรนด์ (จำลอง) · แจ้งสิทธิ์หมดอายุ · โควตาข้อความ LINE |
| แบรนด์ทั้งหมด | `#/brands` | ภาพรวมทุกแบรนด์: ช่องทางที่เชื่อม คนเห็น 7 วัน โพสต์ที่จะออก โพสต์ไม่สำเร็จ · เพิ่มแบรนด์ใหม่ |

สลับแบรนด์ได้จากกล่องด้านบนของเมนู (มือถืออยู่บนสุดของหน้า) · ข้อมูลตัวอย่าง 4 แบรนด์: FitFlow อารีย์, Bean & Co. Café, คลินิกทันตกรรมยิ้มสวย, TechForce · กด “รีเซ็ตข้อมูล” เพื่อเริ่มใหม่

ใช้ได้ทั้งเดสก์ท็อปและมือถือ (มือถือมีแถบเมนูล่าง) · ธีมมืด/สว่าง · รองรับ “ลดการเคลื่อนไหว”

## โครงสร้าง

```
index.html            โครงหน้า + ฟอนต์
assets/app.css        สไตล์ทั้งหมด (token สีที่ :root, ธีมสว่างที่ [data-theme='light'])
assets/app.js         หน้าเว็บทั้งหมด · โหมดตัวอย่าง (localStorage) / โหมดเซิร์ฟเวอร์ (API)
server/index.mjs      เริ่มเซิร์ฟเวอร์ + ตัวตั้งเวลา (ทุก 30 วินาที)
server/app.mjs        HTTP: หน้าเว็บ, API, เข้าสู่ระบบ, OAuth, อัปโหลดรูป
server/connectors.mjs ต่อ API แต่ละแพลตฟอร์ม (Meta, LINE, X, TikTok)
server/scheduler.mjs  หาโพสต์/รอบของกฎที่ถึงเวลา แล้วโพสต์ทีละช่องทาง
server/store.mjs      เก็บข้อมูล (data/state.json) · token เข้ารหัส (data/secrets.json) · รูป (data/media)
server/test/          ทดสอบ (node --test) — ใช้ fetch จำลอง ไม่เรียกแพลตฟอร์มจริง
```

## เริ่มใช้งานจริง

```bash
cd apps/techforce-social
cp .env.example .env          # แล้วแก้ค่าใน .env
openssl rand -base64 32       # เอาค่าที่ได้ใส่ TOKEN_ENC_KEY
npm start                     # หรือ npm run dev = DRY_RUN (ทดสอบระบบโดยไม่โพสต์จริง)
npm test
```

1. ตั้ง `ADMIN_PASSWORD` (≥ 10 ตัวอักษร) และ `TOKEN_ENC_KEY` — ถ้าไม่ครบเซิร์ฟเวอร์จะไม่เริ่ม
2. ตั้ง `PUBLIC_BASE_URL` เป็น **https** ของเซิร์ฟเวอร์ (Instagram, LINE และ TikTok ดึงรูปจาก URL นี้ และใช้เป็น redirect ของ OAuth) — ทดสอบในเครื่องใช้ tunnel เช่น `cloudflared tunnel --url http://localhost:8787` แล้วเอา URL ที่ได้มาใส่
3. สมัคร developer app ของแต่ละแพลตฟอร์ม (ด้านล่าง) แล้วใส่ key ใน `.env` → รีสตาร์ท
4. เปิดหน้าเว็บ → เข้าสู่ระบบ → เพิ่มแบรนด์ → หน้า “บัญชีที่เชื่อม” กดเชื่อมต่อทีละช่องทาง

### ตั้งค่าแต่ละแพลตฟอร์ม

ใส่ **Redirect URI** ในหน้าตั้งค่าของแต่ละแอปให้ตรงทุกตัวอักษร: `{PUBLIC_BASE_URL}/api/oauth/{meta|tiktok|x}/callback`

| แพลตฟอร์ม | สมัครที่ | ค่าใน .env | สิทธิ์ที่ขอ | ข้อควรรู้ |
|---|---|---|---|---|
| Facebook + Instagram | developers.facebook.com → Create App (Business) → เพิ่ม Facebook Login for Business | `META_APP_ID` `META_APP_SECRET` | `pages_show_list` `pages_read_engagement` `pages_manage_posts` `instagram_basic` `instagram_content_publish` `business_management` | ใช้กับเพจที่คุณเป็นแอดมิน/ผู้ทดสอบของแอปได้ทันที · เพจของลูกค้าคนอื่นต้องผ่าน **App Review** + Business Verification ก่อน · IG ต้องเป็นบัญชีธุรกิจ/ครีเอเตอร์ที่ผูกกับเพจ และรับเฉพาะ JPEG |
| TikTok | developers.tiktok.com → Manage apps → เพิ่ม Login Kit + Content Posting API | `TIKTOK_CLIENT_KEY` `TIKTOK_CLIENT_SECRET` | `user.info.basic` `video.publish` | ต้องยืนยันโดเมนของ `PUBLIC_BASE_URL` (โพสต์รูปแบบ PULL_FROM_URL) · ก่อนผ่าน audit โพสต์ได้เฉพาะแบบ “เห็นคนเดียว” |
| X | developer.x.com → Project/App → User authentication settings (OAuth 2.0, Web App) | `X_CLIENT_ID` `X_CLIENT_SECRET` | `tweet.read` `tweet.write` `users.read` `media.write` `offline.access` | ต้องใช้แพ็กเกจ API ที่อนุญาตให้โพสต์ · ข้อความไม่เกิน 280 ตัวอักษร |
| LINE OA | developers.line.biz → Provider → Messaging API channel ของ OA | ไม่ต้อง — กรอกในหน้าเว็บ | Channel access token (long-lived) | โพสต์ = broadcast ถึงเพื่อนทุกคน ใช้โควตาข้อความของแพ็กเกจ OA |
| YouTube Shorts | — | — | — | ยังไม่รองรับ (โพสต์ได้เฉพาะวิดีโอ) |

### ระบบทำงานอย่างไร

- **ตั้งเวลา:** ตัวตั้งเวลาตรวจทุก 30 วินาที โพสต์ที่ถึงเวลาจะถูกโพสต์ทีละช่องทาง ผลแยกรายช่องทาง (โพสต์แล้ว / ได้บางช่องทาง / ไม่สำเร็จ พร้อมข้อความจากแพลตฟอร์ม) · ถ้าเซิร์ฟเวอร์ปิดไปเกิน 6 ชั่วโมงจะไม่โพสต์ย้อนหลัง
- **กฎอัตโนมัติ:** ถึงวัน/เวลาของกฎ ระบบสร้างโพสต์จากกฎแล้วโพสต์ให้ ครั้งเดียวต่อรอบ · กฎแบบเหตุการณ์ (เช่น คลาสใกล้เต็ม) ต้องต่อข้อมูลจากระบบอื่นภายหลัง
- **รูป:** หน้าเว็บย่อรูปเหลือด้านยาว 1600px (JPEG) ก่อนอัปโหลด · ถ้าเลือกเทมเพลตของแบรนด์ หน้าเว็บจะวาดเป็นรูป 1080×1080 ให้ก่อนโพสต์
- **กันโพสต์ถี่เกิน:** ไม่เกิน 3 โพสต์/วัน/ช่องทาง/แบรนด์
- **token หมดอายุ:** X และ TikTok ต่ออายุให้เองด้วย refresh token · เชื่อมใหม่แล้วโพสต์ที่ล้มเหลวจะลองใหม่ให้

### ความปลอดภัย

- token ของแพลตฟอร์มเข้ารหัส AES-256-GCM ด้วย `TOKEN_ENC_KEY` และไม่ถูกส่งให้หน้าเว็บเลย
- ทุก API ต้องเข้าสู่ระบบ (cookie HttpOnly, SameSite=Lax, Secure เมื่อเป็น https) · ใส่รหัสผิด 5 ครั้งล็อก 15 นาที · คำขอที่เปลี่ยนข้อมูลต้องมี header `X-TFS` (กัน CSRF)
- OAuth ใช้ `state` แบบสุ่มหมดอายุใน 10 นาที · X ใช้ PKCE
- รูปที่ `/media/*` เปิดสาธารณะ (แพลตฟอร์มต้องดึงไปได้) แต่ชื่อไฟล์สุ่ม 128 บิต
- ห้าม commit `.env` และโฟลเดอร์ `data/` (อยู่ใน `.gitignore`) · สำรองโฟลเดอร์ `data/` สม่ำเสมอ

### ข้อจำกัดตอนนี้

- ผู้ใช้คนเดียว (รหัสผ่านผู้ดูแล) ยังไม่มีบัญชีทีม/สิทธิ์แยกตามลูกค้า · เก็บข้อมูลเป็นไฟล์ JSON (เหมาะกับเซิร์ฟเวอร์เครื่องเดียว)
- ยังไม่รองรับวิดีโอและอัลบั้มหลายรูป · ยังไม่ดึงยอดคนเห็นจริงจากแพลตฟอร์ม (การ์ดผลลัพธ์แสดง 0)
- โค้ดต่อ API เขียนตามเอกสารของแต่ละแพลตฟอร์มและทดสอบด้วย API จำลองแล้ว **ยังไม่ได้ทดสอบกับบัญชีจริง** — ควรลองโพสต์ทดสอบทีละช่องทางก่อนใช้กับลูกค้า
