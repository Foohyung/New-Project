# ADR-0001: ใช้ Payload CMS ทำหลังบ้านของเว็บไซต์บริษัท

- สถานะ: Proposed
- วันที่: 2026-10-16
- ผู้ตัดสินใจ: (รอ reviewer อนุมัติ)

## บริบท

ลูกค้าเว็บไซต์บริษัทต้องเพิ่มและแก้ไขสินค้า รูปภาพ และเนื้อหาหน้าเว็บได้เอง ระบบหลังบ้านต้องใช้ง่ายสำหรับคนที่ไม่ใช่โปรแกรมเมอร์ และต้องขายได้ในราคาเริ่มต้น ฿990/เดือน จึงต้องใช้เวลาพัฒนาน้อยและดูแลง่าย

มาตรฐาน §2.4 กำหนดว่าการเพิ่ม library ระดับ core ต้องมี ADR

## การตัดสินใจ

ใช้ **Payload CMS** ฝังอยู่ใน Next.js app ตัวเดียวกับหน้าเว็บ และเก็บข้อมูลใน PostgreSQL ตามมาตรฐาน

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **Payload CMS** | รันใน Next.js app เดียวกัน, config เป็น TypeScript, ใช้ Postgres, มี admin UI, access control, upload, draft/version ในตัว, license MIT | เพิ่ม dependency ระดับ core และมีระบบ auth ของตัวเอง |
| เขียนหลังบ้านเอง (Prisma + Better Auth) | ตรงมาตรฐาน 100% | ต้องสร้างฟอร์ม, upload, ตาราง และสิทธิ์เองทั้งหมด ใช้เวลาหลายสัปดาห์ต่อเทมเพลต |
| Headless CMS แบบ SaaS | ไม่ต้องดูแล server ของ CMS | มีค่าบริการต่อลูกค้า ข้อมูลอยู่นอกระบบเรา (กระทบ PDPA) และต้นทุนไม่เข้ากับราคา ฿990/เดือน |

## ผลที่ตามมา

**ข้อดี:** ส่งมอบเว็บได้ใน 7–14 วัน และลูกค้าได้หลังบ้านที่ใช้งานง่ายตั้งแต่วันแรก

**ข้อเสีย / ความเสี่ยง และสิ่งที่ต้องทำเพิ่ม:**

- **ขัดกับ §10.1 (ใช้ Better Auth เท่านั้น)** สำหรับผู้ใช้หลังบ้าน — ต้องบังคับ 2FA ให้ admin/editor (ผ่าน plugin) หรือวางหน้า `/admin` ไว้หลัง Cloudflare Access ก่อนขึ้น production
- ต้องตั้ง access control ของ collection ให้ deny by default (§10.2) และเขียน test สิทธิ์ของ editor
- การอัปโหลดรูปต้องผ่านกฎ §10.7 (ตรวจ magic bytes, re-encode ด้วย sharp)
- ต้องตรวจสถานะการดูแลโปรเจกต์ เวอร์ชันล่าสุด และ license ตามเกณฑ์ §2.4 อีกครั้งก่อนเริ่ม scaffold

## วันทบทวน

ก่อน scaffold โปรเจกต์ company-website
