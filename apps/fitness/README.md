## โครงสร้างโฟลเดอร์

`src/web` = หน้าบ้าน (Frontend) · `src/api` = หลังบ้าน (Backend) · ข้างในแบ่ง **ชนิด > เรื่อง > โฟลเดอร์ > ไฟล์** เช่น `src/web/app/dashboard/dashboard/dashboard.page.tsx`, `src/api/dal/members/members/members.dal.ts` · เส้นทาง URL ของ Next.js อยู่ที่ `app/` นอก src — รายละเอียดและกฎตั้งชื่อดูที่ [docs/STRUCTURE.md](docs/STRUCTURE.md) · รูปแบบ UI มาตรฐาน (popup ยืนยัน/แจ้งผล ปุ่มท้ายแถว ปุ่มย้อนกลับ แนบไฟล์) และข้อยกเว้นจากมาตรฐานกลางดูที่ [docs/UI.md](docs/UI.md)

## หน้าเว็บ

```bash
pnpm --filter @app/fitness dev   # http://localhost:3001
```

**ใช้โฟลเดอร์นี้เดี่ยว ๆ (ไม่ต้องมี monorepo):** โฟลเดอร์ `apps/fitness` ไม่พึ่ง package กลางแล้ว (utils/security อยู่ใน `src/api/lib`) ยกไปทั้งโฟลเดอร์ได้เลย ไม่ต้องเอา `node_modules` และ `.next` ไปด้วย ต้องมี Node 24 + pnpm 12

```bash
pnpm install && pnpm build
```

**ฐานข้อมูล (ครั้งแรก):** สร้างฐานข้อมูล MySQL (`CREATE DATABASE fitflow CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`) ใส่ `DATABASE_URL`, `SEED_OWNER_*` และ `SEED_ADMIN_*` ใน `.env` (ตั้งรหัสผ่านอย่างน้อย 8 ตัวอักษร) แล้วรัน

```bash
pnpm db:migrate   # สร้างตาราง (prisma/migrations) — รันซ้ำทุกครั้งที่อัปเดตโค้ด เช่น 0007 เพิ่มตาราง owner_branches, 0008 เพิ่ม active_from/active_to ของ users, 0009 เพิ่ม must_change_password, 0010 ตาราง password_reset_requests
pnpm db:seed      # แพ็กเกจ · รอบแจ้งเตือน · บัญชีเจ้าของและ admin (รันซ้ำได้ ไม่เปลี่ยนรหัสผ่านบัญชีเดิม)
pnpm db:sample    # (ไม่บังคับ) ข้อมูลตัวอย่าง — เพิ่ม --reset เพื่อล้างทุกตารางก่อน ห้ามใช้กับฐานข้อมูลจริง
```

**Deploy:** ตั้งค่าในไฟล์ `.env` (ดู `.env.example`) แล้วรัน

```bash
pnpm install && pnpm db:migrate && pnpm build && pnpm start   # start คัดลอกไฟล์ static + อ่าน .env + รัน .next/standalone/server.js ให้เอง
```

- ค่าเริ่มต้น `PORT=3001`, `HOSTNAME=127.0.0.1` (รับเฉพาะในเครื่อง ให้ IIS/Caddy ที่มี HTTPS อยู่ด้านหน้า) — cookie เข้าสู่ระบบเป็น `secure` ต้องเข้าผ่าน https
- ทดสอบผ่าน `http://IP:3001` ก่อนมีโดเมน: ตั้ง `HOSTNAME=0.0.0.0` และ `ALLOW_HTTP=1` ใน `.env` — **ห้ามเปิดตอนใช้งานจริง**
- ห้ามใช้ `pnpm dev` บน server: โหมด dev บล็อก JavaScript เมื่อเปิดผ่าน IP/โดเมน (ปุ่มกดไม่ได้)
- test ของ DAL (`src/api/test/*/*/*.dal.test.ts`) รันกับ MySQL ที่ `TEST_DATABASE_URL` เท่านั้น ไม่ตั้ง = ข้าม

## Responsive (§15.2)

ผ่านการตรวจอัตโนมัติที่ 320 / 390 / 768 / 1024 / 1440px: ไม่มี scroll แนวนอน, พื้นที่แตะ ≥ 44px, ตัวอักษรใน input ≥ 16px, hover อยู่ใน `@media (hover: hover)` และรองรับ reduced motion

| ขนาดจอ | เมนู |
|---|---|
| มือถือ (< 768px) | bottom tab bar |
| แท็บเล็ต (768–1023px) | sidebar แบบไอคอน |
| เดสก์ท็อป (≥ 1024px) | sidebar เต็ม |

**เมนู:** กลุ่ม "ตั้งค่า" (บัญชีผู้ใช้ · บทบาทและสิทธิ์ · แบรนด์สาขา) อยู่ล่างสุดของเมนูเสมอ

**Animation เปลี่ยนหน้า:** แถบ wipe พร้อมชื่อหน้า ยาว 1.5 วินาที (`WIPE_MS` ใน `src/web/lib/layout/layout/layout.motion-routes.ts`) · หน้าที่จะมี animation ต้องอยู่ใน map `EXACT` ของไฟล์เดียวกัน (รวมหน้าตั้งค่าแล้ว) · ปิดอัตโนมัติเมื่อเครื่องตั้ง reduced motion

**Popup แจ้งผล:** ทุกการ**แก้ไข/ลบ/ยกเลิก**ข้อมูลมี popup ยืนยันก่อน (`ConfirmForm` · ลบใช้ปุ่มสีแดง) แล้วแสดง popup กลางจอเมื่อสำเร็จ (`showSuccess` — "แก้ไขสำเร็จ" / "ลบสำเร็จ" / "ทำรายการสำเร็จ" ค่าเริ่มต้นของ `ActionButton` ที่มี `confirm`) · การเพิ่ม/ส่งข้อมูลอื่นแสดง toast มุมจอ 3.5 วินาที (`toast()` ผูกกับ `ResultMessage`) · ฟอร์มใหม่ที่แก้/ลบข้อมูลให้ใช้ `ConfirmForm` + `ResultMessage successTitle` เสมอ

**ช่องแนบไฟล์:** ใช้ `FileDrop` (`src/web/components/ui/ui/ui.file-drop.tsx`) — กล่องลากวาง/กดเลือก พรีวิวรูป ปุ่มเปลี่ยน/เอาออก และตรวจขนาดฝั่ง client (server ยังตรวจซ้ำ)

อุปกรณ์หลัก: สมาชิกใช้มือถือ / LINE in-app browser, เคาน์เตอร์ใช้แท็บเล็ตแนวนอน, ผู้จัดการใช้เดสก์ท็อปและมือถือ

## ขอบเขตระบบ

- **สมาชิก:** สมัคร, แพ็กเกจ, ต่ออายุ, พักสมาชิก, แจ้งเตือนใกล้หมดอายุ
- **เช็กอิน:** QR code จากมือถือสมาชิก, ปฏิเสธอัตโนมัติเมื่อหมดอายุ
- **คลาส & เทรนเนอร์:** ตารางคลาส, จองที่นั่ง (จำกัดความจุ), จองเทรนเนอร์ส่วนตัว
- **การเงิน:** PromptPay QR, ตัดบัตรรายเดือน (Omise), ใบเสร็จ, รายงานรายได้
- **แจ้งเตือน:** LINE OA
